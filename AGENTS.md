# Project instructions

- Keep `README.md` and this file aligned with every feature or dependency change. Keep all third-party credits and license references in README.
- Keep the application fully static. GitHub Pages hosts the built site at `/chesstrapboard/` on `https://lukas.zapletalovi.com`; runtime assets come from this repository.
- Maintain one full-game opening trainer. Opening selection is optional: when unset, do not select or display a random named line. Choose a fresh legal move at each CPU turn from the committed common opening book, which filters the full Lichess position book using sampled rated-game counts. Use the engine when the common book has no continuation. When an opening is explicitly selected, follow that line while applicable, then any matching position-indexed full database continuation, and only then normal engine play. Allow the first board interaction or New game to start play. Label the database phase clearly and prefer book moves with a further continuation over immediate book leaves, while retaining random choice among continuing lines. It may seek engine-validated trap opportunities from its third move even while book moves exist, and grades moves only afterward. Optional live evaluation may show an ungraded score during play and defaults off.
- Accept shareable URL parameters for ECO opening code, optional exact opening name, side, difficulty, mistake frequency, opportunity size, and live evaluation. Valid links start a game after opening data loads; a valid link uses new-visitor defaults for omitted training settings rather than saved preferences, and setting changes keep the URL current. Keep New ECO game beside New game. Enable it only for a selected opening whose final position is playable; start from that exact position with a fresh move history. Preserve the setup FEN in PGN and review, show actual move numbers in the move list, and use the original opening ply for trap eligibility while keeping review and take-back indices relative to the new game.
- Keep CPU difficulty separate from the frequency and size of deliberate mistake attempts. Default new visitors to Intermediate difficulty and 95% deliberate mistake attempts; offer Off, 25%, 50%, 85%, and 95% attempt chances. Validate generated candidate moves and replies with `chess.js`, then confirm the advantage with a separate engine search from the resulting position; when no candidate qualifies, prefer a selected-line move, then a legal database move, then a normal engine move. For normal engine play, randomly choose between the top two legal centipawn moves only when their scores differ by at most 20 centipawns; leave mate scores alone. Count attempted checks separately from generated opportunities and keep the postgame console diagnostics accurate. Keep the long settings explanations, including opportunity-size ranges, in hover text.
- Keep Lichess opening source TSV, the pinned CC0 rated-game count snapshot in `data/common-move-counts.json`, and deterministic, browser-ready processed `openings.json`, `book.json`, and `common-book.json` in Git. Build the full position book from validated source moves and the common book from sampled play counts; merge transpositions by four-field FEN. Keep the common-book sample and filtering method documented in `data/COMMON_BOOK.md`; verify all processed outputs in CI. Data updates are explicit.
- Keep Take back between New game and End & Analysis. It undoes the player's latest move and any CPU reply, even if the game just ended; cancel searches and review, drop opportunity checks and generated records for undone moves, recompute opening progress, and leave the player to move.
- Keep the browser engine files in Git. Record the exact upstream release, checksums, GPL license, and corresponding source location.
- Attribute every external package, dataset, sound, and artwork with verified license terms before adding it.
- The move tap and opportunity chime are synthesized in `src/sound.ts`; no external audio assets are included. Both default on with shared volume at 50%. The Opportunity hint & sound toggle controls the chime and the brief cue above the board. A validated deliberate CPU opportunity plays the chime after the move tap; a confirmed forced mate for the player after any CPU move also creates an opportunity and plays the chime, even if no deliberate attempt occurred. Confirm incidental mate cues with a deeper bounded search before signaling, ignore the pawn-size band for forced-mate candidates, and preserve the cue and immediate move-list underline/reply mark. Checkmate or stalemate instead plays only the chime, for either side. Keep opportunity marks for postgame review.
- Keep one clickable move list for play and postgame review. Place the always-visible evaluation card above Moves and the selected move's suggested line directly below Evaluation; clip the line to one row and expose its full text on hover. Scrub the validated principal variation on the board as the pointer moves across the line, then restore the selected game position shortly after pointer leave without changing move selection. Keep review progress and navigation below Copy PGN. Use sparse `!`, `!!`, `?`, and `??` marks during play as cached analysis completes and after the game: mark losses of at least 200 or 500 centipawns, include clearly missed or newly allowed mates, and praise an engine-best move only when the next-best line is at least 180 or 400 centipawns worse. Search two principal variations for review, and do not mark moves without enough scores to justify a mark. Underline generated CPU opportunity moves as soon as they are recorded; mark the player's reply `!` when found or `?` when missed, overriding its general annotation. Build the review incrementally from cached positions in move order, show it immediately when the game ends, silently fill gaps left by fast play, and print completed diagnostics to the JavaScript console. During player turns, silently pre-analyze the current position first and then older reached positions in a separate engine Worker, with a 500 ms budget normally and 1,200 ms near generated opportunities; stop once covered, interrupt on player moves or CPU turns, and pause for engine hints, live evaluation searches, and hidden tabs. Cache completed results by full FEN and their time and variation budgets, reuse them for review, and search again when an opportunity needs a deeper result. After the game, fill missing positions at 260 ms or 850 ms near opportunities without blocking the record. Show move-list grades as background results arrive. Update move marks without redrawing the board. Keep the selected board square, legal-move highlights, and keyboard focus through any other redraw of the same position; reset selection when the position, orientation, or playable side changes. Keep the numeric evaluation hidden during play unless live evaluation is enabled, and keep the suggested line hidden until the game ends. Re-evaluate candidates after the game, allow modest score drift, and leave vanished advantages unconfirmed. Preserve wheel and arrow-key navigation, a blank evaluation score by default, and one Copy PGN button without a visible notation box or success label. Keep the last live score visible while the next position is evaluated. Keep Hint beside Copy PGN; in book positions validate and shuffle all distinct database moves plus a matching selected-line move, then cycle through them on repeated presses and loop without reshuffling until the position changes. Outside the book, keep the engine hint and its hide toggle. Mark the hinted source and destination on the board with distinct colors, and clear stale hints when the position changes. The board colors and button state are enough feedback; do not add a separate hint status line. Cancel stale live searches when the viewed position changes.
- Keep `.github/FUNDING.yml` limited to the `lzap` GitHub Sponsors username, matching the location and filename GitHub recognizes.
- Use `chess.js` as the authoritative rules and PGN implementation. Validate all book and engine moves through it.
- Run `npm run check`, focused tests, `npm run verify:data`, `npm run verify:engine`, `npm run verify:licenses`, and `npm run build` for code changes. Include a real-browser check when engine or Pages asset paths change.
- Follow the user's global Git instructions: pull `main` before commits, inspect recent commit style, make small reviewable commits, and ask before any push while showing changed files and destination.
