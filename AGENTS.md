# Project instructions

- Keep `README.md` and this file aligned with every feature or dependency change. Keep all third-party credits and license references in README.
- Keep the application fully static. GitHub Pages hosts the built site at `/chesstrapboard/` on `https://lukas.zapletalovi.com`; runtime assets come from this repository.
- Maintain one full-game opening trainer. The CPU follows the selected opening while applicable, may seek engine-validated trap opportunities from its third move, and grades moves only afterward. Optional live evaluation may show an ungraded score during play and defaults off.
- Keep CPU difficulty separate from the frequency and size of deliberate mistake attempts. Offer Off, 25%, 50%, 85%, and 95% attempt chances, with 85% selected for new visitors. Validate generated candidate moves and replies with `chess.js`, then confirm the advantage with a separate engine search from the resulting position; fall back to a book move or normal engine move when no candidate qualifies. Count attempted checks separately from generated opportunities and keep the postgame summary accurate.
- Keep Lichess opening source TSV and deterministic, browser-ready processed data in Git. Data updates are explicit; CI verifies the processed files match their source.
- Keep the browser engine files in Git. Record the exact upstream release, checksums, GPL license, and corresponding source location.
- Attribute every external package, dataset, sound, and artwork with verified license terms before adding it.
- The move tap and opportunity chime are synthesized in `src/sound.ts`; no external audio assets are included. Keep both muted by default and honor the shared volume control. Only a validated deliberate CPU opportunity may trigger the chime and brief non-graded visual cue during play; keep move grades and opportunity explanations for postgame review.
- Keep one clickable move list for play and postgame review. Place the always-visible evaluation card above Moves, and all dynamic review labels, progress, navigation, and detail below Copy PGN so the list stays put. Underline generated CPU moves and color-code found, missed, or partial replies after review. Re-evaluate candidates after the game, allow modest score drift, and leave vanished advantages unconfirmed. Preserve wheel and arrow-key navigation, a blank evaluation score by default, and one Copy PGN button without a visible notation box. Cancel stale live searches when the viewed position changes.
- Use `chess.js` as the authoritative rules and PGN implementation. Validate all book and engine moves through it.
- Run `npm run check`, focused tests, `npm run verify:data`, `npm run verify:engine`, `npm run verify:licenses`, and `npm run build` for code changes. Include a real-browser check when engine or Pages asset paths change.
- Follow the user's global Git instructions: pull `main` before commits, inspect recent commit style, make small reviewable commits, and ask before any push while showing changed files and destination.
